# dsh-portable

Плагин DeepSeek Harness, который переносит установку DSH на другой компьютер целиком:
настройки, историю сессий, вложения, плановые задачи, список проектов и права — одним
архивом, с **холодным восстановлением** вместо перезаписи живых файлов.

[English version](README.md)

```
Настройки → Перенос
  [ Экспорт ]  скачать dsh-portable-<host>-<дата>.tar.gz
  [ Импорт ]   выбрать архив → проверить план → восстановить
```

## Почему импорту нужен перезапуск

DSH держит открытыми журналы сессий, `storages/*.json` и профиль. Замена папки DSH
изнутри работающего процесса либо не удаётся на Windows (открытые хендлы блокируют
переименование), либо затирается следующим сохранением. Поэтому плагин ничего не
подменяет на живую:

1. архив загружается и распаковывается во временную папку рядом с домашней
   (`<родитель home>/.dsh-portable/staging/<id>`);
2. хост сравнивает его с текущей машиной и отдаёт план с предупреждениями;
3. по кнопке **Восстановить** плагин пишет маленький помощник `restore-<id>.ps1`
   (или `.sh` на POSIX) и запускает его отдельно;
4. помощник ждёт выхода DSH, переименовывает текущую папку в
   `<home>.before-<время>`, ставит на её место распакованную и запускает DSH заново;
5. если после переименования что-то пошло не так, помощник возвращает бэкап обратно.

Ничего не удаляется: прежняя папка остаётся рядом с новой.

## Установка

Нужен DSH `0.2.2-rc.1` или новее, а также `git` и `pnpm` для установки бандла.

В интерфейсе DSH: **Настройки → Плагины → установить** и указать спецификацию

```
github:breeeew/dsh-portable
```

или из терминала:

```powershell
dsh plugin --profile desktop add github:breeeew/dsh-portable
```

После установки перезапустите DSH — в настройках появится раздел **Перенос**.

Удаление — снятием бандла в **Настройки → Плагины**. Архивы и бэкапы при этом не
трогаются.

## Что попадает в архив

Всё содержимое домашней папки DSH (`%USERPROFILE%\.dsh` на Windows, `~/.dsh` на
POSIX) рекурсивно, кроме:

| Исключено | Причина |
|---|---|
| `dsh-runtimes/` | скачанный рантайм Python/Node, ~250 МБ; включается галочкой |
| `cache/` | пересобираемые кэши |
| `*.lock` | временные lock-файлы |
| `profiles/*/.plugin-manager/logs/` | логи установки плагинов |
| `.git/` | служебные файлы, если папка под git |

Опции экспорта:

| Опция | По умолчанию | Смысл |
|---|---|---|
| Учётные данные (`.credentials.yaml`) | включены | без них на новой машине придётся войти заново |
| Рантайм Python/Node | выключен | нужен, только если на новой машине не будет интернета |

Архив — обычный `tar.gz` с `manifest.json` в корне: формат, дата, версия DSH, хост,
пользователь, состав, количество сессий, поколения формата журналов и список проектов
с абсолютными путями.

## План импорта и предупреждения

План считается на хосте и показывается до восстановления:

- **Отсутствующие папки проектов.** История останется читаемой и сохранит проект, но
  продолжить сессию нельзя без её рабочей папки. Плагин не переписывает записанные
  пути — это молча испортило бы историю.
- **Есть учётные данные** в архиве.
- **Есть `.env`** — настройки прокси привязаны к машине, поэтому импорт `.env` —
  отдельная галочка, по умолчанию выключена.
- **Разные версии DSH**, когда обе стороны сообщают версию рантайма.
- **Более новый формат журналов сессий**, чем знает плагин (`v0`–`v4`) — блокирует.
- **Другая ОС** у архива.
- **Не хватает места** (нужно примерно вдвое больше распакованного объёма: копия в
  staging плюс сохранённый бэкап) — блокирует.
- **Рантаймы исключены** — DSH скачает их при первом запуске, нужен интернет.

Блокирующие предупреждения выключают кнопку восстановления; распакованную копию можно
удалить.

## После восстановления

- Прежняя папка лежит в `<home>.before-<время>`.
- Лог помощника: `<родитель home>/.dsh-portable/logs/restore-<id>.log`.
- Скрипт можно запустить вручную позже: при отсутствии staging он ничего не меняет и
  возвращает бэкап.

### Откат

1. Полностью закрыть DSH, включая значок в трее.
2. Переименовать восстановленную `%USERPROFILE%\.dsh` в `.dsh.restored`.
3. Переименовать `%USERPROFILE%\.dsh.before-<время>` в `.dsh`.
4. Запустить DSH.

## Ограничения

- **Импорт заменяет всю папку**, включая профиль и его `node_modules`. Плагины,
  установленные на новой машине, но отсутствующие в архиве, исчезнут; плагины
  источника переедут вместе с архивом (поставьте этот плагин на источник до экспорта,
  если хотите, чтобы он пережил восстановление).
- **Одинаковые абсолютные пути дают точное совпадение.** Записи проектов и заголовки
  сессий хранят абсолютные пути. При другом имени пользователя или раскладке дисков
  история останется видимой под старым проектом, но автоматически перепривязать её
  нельзя.
- Помощник — сгенерированный скрипт, а не служба. Если DSH не закрыть в течение часа,
  он завершится, ничего не изменив.
- Журналы сессий дописываются; экспорт при работающем DSH может поймать сессию в
  момент копирования. Формат переживает оборванный хвост и чинит его при следующем
  открытии.
- Архив содержит токены и, возможно, рабочие данные. Передавайте его только по
  защищённому каналу.
- Поддерживаются Windows и POSIX (CLI-установки macOS/Linux); десктопное приложение
  сейчас только под Windows.

## Разработка

```powershell
node --test
```

Тесты покрывают tar-писатель и читатель (юникодные имена, длинные пути, отказ при
traversal, битой контрольной сумме и обрезанном архиве), манифест и план, полный цикл
экспорт → импорт → применение на временной папке, регистрацию клиентского бандла в VM
и реальный PowerShell-скрипт (подмена и откат) на Windows.

```
lib/archive.js   tar + gzip без зависимостей, безопасная распаковка
lib/home.js      сканирование, манифест, план, имена бэкапов, скрипты восстановления
lib/index.js     host-плагин: аутентифицированные маршруты /api/portable/*
lib/client.js    браузерный плагин: Настройки → Перенос
cordis.patch.yml слой бандла, который монтирует host-строку
```
